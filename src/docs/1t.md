### **Refactoring for Atlas Vector Search**

To switch from Pinecone to Atlas, you need three things:
1.  **A Search Index** (Created in the Atlas UI/API).
2.  **A Vector Field** in your Mongoose Schema.
3.  **An Aggregation Pipeline** using `$vectorSearch`.

#### **1. Schema Update (`Message.js` or `Session.js`)**
You must add a field to store the vector Mistral gives you.

```javascript
// In Message.js
const MessageSchema = new mongoose.Schema({
  // ... existing fields
  embedding: {
    type: [Number],
    required: false, // Only populate if we want this message searchable
    index: false     // Standard indexes don't work for vectors; Atlas uses Search Indexes
  }
});
```

#### **2. The Atlas Vector Search Tool (Unified)**
Instead of a separate tool, we should enhance your `mongoDBSearchTool` to handle **Semantic Search**.

```javascript
// NEW: Semantic Search Logic for your MongoDB Tool
import { generateEmbedding } from '../services/embeddingService.js';

async function semanticSearch(params) {
  const { query, limit = 5, collection = 'messages' } = params;
  
  // 1. Generate the vector for the user's natural language query
  const vector = await generateEmbedding(query);

  // 2. Execute Atlas Vector Search via Aggregation
  const results = await Message.aggregate([
    {
      "$vectorSearch": {
        "index": "vector_index", // The name you gave your index in Atlas
        "path": "embedding",
        "queryVector": vector,
        "numCandidates": limit * 10,
        "limit": limit
      }
    },
    {
      "$project": {
        "content": 1,
        "role": 1,
        "sessionId": 1,
        "score": { "$meta": "vectorSearchScore" } // See how relevant it is
      }
    }
  ]);

  return {
    type: 'semantic_search',
    query,
    count: results.length,
    results
  };
}
```

### **Strategic Review: Atlas vs. Pinecone for Victor/Sentinel**

#### **Pros (The Wins)**
*   **Atomic Transactions:** When Victor saves a thought, he can save the text and the vector in one `save()` call. You never have a message in your DB that "doesn't exist" in your memory index.
*   **Hybrid Filtering:** You can filter by `sessionId` AND `semantic relevance` in a single query. Pinecone metadata filtering is limited; MongoDB's is infinite.
*   **Cost:** You are already paying for Atlas. You likely won't need a separate Pinecone subscription.

#### **Cons (The Trade-offs)**
*   **Search Index Latency:** Atlas Vector Search indexes are "eventually consistent." There is a slight delay (seconds) between Victor saving a thought and Sentinel being able to find it via vector search.
*   **Configuration:** You must manually create the `vector_index` in the Atlas UI, specifying 1536 dimensions (for Mistral-embed).

### **Implementation Roadmap**

1.  **Atlas Setup:** Go to Atlas UI -> Search -> Create Search Index -> **JSON Editor**. Use this configuration:
    ```json
    {
      "fields": [{
        "type": "vector",
        "path": "embedding",
        "numDimensions": 1536,
        "similarity": "cosine"
      }]
    }
    ```
2.  **Victor's Memory Hook:** Update your `record_thought` tool or `saveHistory` logic to call `generateEmbedding()` automatically.
    *   *Victor Mode:* Embedding every thought is great for deep recall.
    *   *Sentinel Mode:* Embedding only "High Importance" triage events saves costs.
3.  **Semantic Loop Detection:** In your `ToolExecutionManager.js`, replace the Pinecone logic with a `$vectorSearch` that looks for similar `signatures` in the database.
