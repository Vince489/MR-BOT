To integrate **Atlas Vector Search** into your existing MongoDB architecture, you need to modify your Mongoose schemas and update your search tool logic. This will allow Victor to move beyond simple keyword filtering and perform semantic "meaning-based" searches across your message history.

### 1. Update the Message Schema (`Message.js`)
You must add an `embedding` field to the `messageSchema` to store the high-dimensional vectors generated by the Mistral embedding service.

**Modification:**
```javascript
// In Message.js, add the embedding field to messageSchema
const messageSchema = new Schema({
  session: { type: Schema.Types.ObjectId, ref: 'Session', required: true, index: true },
  role: { type: String, enum: ['user', 'assistant', 'system', 'tool'], required: true },
  content: { type: String, default: "" },
  // ADD THIS FIELD
  embedding: {
    type: [Number], // Mistral-embed returns 1024 dimensions
    default: undefined,
    index: false // Defined in Atlas UI, not via Mongoose index
  },
  // ... rest of your schema
}, { timestamps: true });
```
* **Why:** Mongoose cannot manage Atlas Vector Indexes directly; you must define the index in the MongoDB Atlas dashboard.

### 2. Update the Search Tool Logic (`mongodb_search_tool.js`)
Modify your `performMongoDBSearch` function to include a `semantic_search` operation. This logic will first call your `generateEmbedding` service and then use the `$vectorSearch` aggregation stage.

**Implementation Suggestion:**
```javascript
import { generateEmbedding } from '../services/embeddingService.js';

async function performSemanticSearch(params) {
  const { query, limit = 5, sessionId } = params;
  
  // 1. Convert natural language query into a vector
  const queryVector = await generateEmbedding(query);
  
  // 2. Resolve session if provided to filter results
  let resolvedId = sessionId ? await resolveSessionId(sessionId) : null;

  // 3. Atlas Vector Search Aggregation
  const pipeline = [
    {
      $vectorSearch: {
        index: "vector_index", // Name must match your Atlas dashboard config
        path: "embedding",
        queryVector: queryVector,
        numCandidates: 100,
        limit: limit,
        // Optional: Filter by session to stay in current context
        ...(resolvedId && { filter: { session: resolvedId } })
      }
    },
    {
      $project: {
        content: 1,
        role: 1,
        score: { $meta: "vectorSearchScore" }, // Relevancy ranking
        createdAt: 1
      }
    }
  ];

  return await Message.aggregate(pipeline);
}
```

### 3. Asynchronous Embedding Generation
Since generating embeddings via an external API (Mistral) adds latency, do not make the user wait for this during the primary chat loop. Modify your `saveMessages` static method to trigger embedding generation in the background.

**Modification to `Message.statics.saveMessages`:**
```javascript
messageSchema.statics.saveMessages = async function(sessionId, newMessages) {
  try {
    const session = await mongoose.model('Session').findOne({ sessionId });
    // ... existing save logic ...
    
    const savedDocs = await this.insertMany(messageDocs);

    // BACKGROUND TASK: Generate embeddings for new user/assistant text
    savedDocs.forEach(async (doc) => {
      if (doc.content && (doc.role === 'user' || doc.role === 'assistant')) {
        try {
          const vector = await generateEmbedding(doc.content);
          await mongoose.model('Message').updateOne({ _id: doc._id }, { embedding: vector });
        } catch (err) {
          console.error(`Failed to background-embed message ${doc._id}:`, err);
        }
      }
    });

    return true;
  } catch (error) { /* ... */ }
};
```

### 4. Atlas Index Configuration
Once your code is updated, you must go to your **MongoDB Atlas Dashboard** and create a search index on the `messages` collection with the following JSON configuration:

```json
{
  "fields": [
    {
      "numDimensions": 1024,
      "path": "embedding",
      "similarity": "cosine",
      "type": "vector"
    },
    {
      "path": "session",
      "type": "filter"
    }
  ]
}
```
* **numDimensions**: Must be **1024** to match the `mistral-embed` model output.
* **similarity**: **Cosine** is the industry standard for language embeddings to ensure the most relevant results.
